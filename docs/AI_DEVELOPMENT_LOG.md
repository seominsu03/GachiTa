- 오류 — 도착지를 고른 뒤 ‘이 위치로 확정’을 누를 수 없었다.
- 해결 — 검색 결과와 지도에서 직접 고른 위치 모두 확정할 수 있도록 조건을 수정했다.
- 결과 — 사용자가 확정 동작과 두 핀 표시를 확인했다.

## 2026-11-16 기록 — 선택한 위치를 카드에서 알 수 없음

- 오류 — 출발지·도착지를 선택한 뒤에도 카드에 ‘위치 선택됨’처럼 모호하게 표시돼 어느 곳인지 알기 어려웠다.
- 해결 — 검색 결과를 그대로 고르면 장소명을, 지도에서 핀을 옮겨 고르면 건물명 후보 또는 도로명 주소를 표시하도록 수정했다.
- 결과 — 사용자가 제공한 Android Expo Go 화면에서 출발지와 도착지 카드에 각각 선택한 도로명 주소가 표시되는 것을 확인했다.
- 후속 문제(2026-11-17) — 건물이나 도로 근처를 선택해도 도로명 주소를 찾지 못해 위치를 확정하기 어려웠다.
- 후속 해결 — 도로명 주소가 없으면 지번 주소를 표시하고, 주소를 찾지 못해도 지도에서 확정한 좌표를 유지해 위치 선택과 이후 경로 조회에 사용할 수 있게 했다.
- 후속 확인 — 사용자가 휴대폰에서 지번 주소 표시와 위치 적용을 확인했다. 주소 확인 불가가 실제로 표시되는 사례는 확인하지 못했다.

## 2026-11-17 — 지도·탑승 기능 dev 통합 검사

- 문제 — 두 브랜치가 방 목록·방 관리·서버 설정 파일을 함께 수정해 병합 충돌이 발생했다.
- 해결 — 정산 전 방 목록 표시와 탑승 동선을 유지하면서 지도 장소 변경·긴 주소 표시·경로 조회를 함께 반영했다. 새 방과 기존 방이 뒤섞여 보이던 목록은 모집 상태와 진행 상태를 나눠 표시하고, 긴 출발지·도착지 문구가 화면 밖으로 잘리지 않도록 배치를 조정했다.
- 확인 — 통합된 `dev`에서 TypeScript 검사, 린트, 백엔드 테스트가 통과했다.
- 남은 확인 — 목록 재배치와 긴 주소의 통합 `dev` 휴대폰 표시 결과는 이 기록에서 별도로 확인하지 않았다. 운행·정산까지의 전체 흐름도 확인이 남아 있다.

## 2026-11-17 — 정원이 찬 방의 인원 재변경 차단

- 문제 — 정원을 줄여 현재 참여 인원과 같아진 뒤 다시 늘릴 수 있어, 모집 완료된 방의 정원을 변경하지 못하게 해 달라는 요구와 달랐다.
- 해결 — 현재 참여 인원이 정원을 채운 경우 인원 수정 버튼을 비활성화하고, 서버도 변경 요청을 `ROOM_FULL`(409)로 거절하도록 했다.
- 결과 — 방장 포함 2/2명인 방에서 3명으로 늘리는 요청이 거절되는 백엔드 통합 테스트와 타입 검사가 통과했다. 버튼 비활성화는 실제 휴대폰에서 별도 확인이 필요하다.

- 확인 — TypeScript 검사와 `git diff --check`는 통과했다. 변경 화면은 사용자가 휴대폰에서 확인했다.
- 남은 작업 — 해당 로컬 환경에서 의존성을 복구한 뒤 린트를 다시 실행해야 한다. 위의 채팅 통합 당시 코드 린트 오류 3건과는 별개다.

## 2026-11-21 — 중복 가상 택시 단계 요청 방지

- 문제 — 최초 구현은 `POST /taxi/advance`를 다시 보내면 서버가 다음 단계로 한 번 더 진행해, 중복 탭이나 재전송 시 단계를 건너뛸 수 있었다. 실제 휴대폰에서 발생한 오류는 아니며 코드 검토 중 확인한 위험이다.
- 해결 — 클라이언트가 본 현재 단계 `expectedStatus`를 요청에 포함하고, 서버가 저장된 방 상태와 다르면 `TAXI_STAGE_CHANGED`(409)로 거절하도록 했다.
- 결과 — 중복 요청이 거절되고 탑승 확인부터 `SETTLING`까지 순서대로 진행되는 백엔드 통합 테스트가 통과했다. TypeScript 검사와 린트도 통과했다.

## 2026-11-23 — 정산 완료 후 채팅방 이동 실패

- 오류 — 정산 완료 화면의 ‘채팅방으로 돌아가기’를 누르면 채팅방 대신 ‘채팅 화면 연결’ 안내 창이 열렸다.
- 원인 — 정산 화면에 이전 시연용 모달 동작이 남아 있었고, 이미 구현된 방 채팅 경로를 호출하지 않았다.
- 해결 — 완료 화면 버튼을 해당 `roomId`의 채팅방으로 직접 이동하도록 바꾸고 사용하지 않는 안내 모달을 제거했다.
- 확인 — TypeScript 검사와 린트 통과. 사용자가 실제 휴대폰에서 버튼을 눌러 채팅방으로 이동하는 것을 확인했다.

## 2026-11-23 — 정산 완료 방 보관 기능의 완료 시각 저장 오류

- 오류 — 완료 시각 기록을 추가한 뒤 백엔드 통합 테스트에서 `detached entity passed to persist: TaxiRoom`과 `null identifier (RoomCompletion)`가 발생했다.
- 원인 — 완료 기록과 기존 방을 JPA 일대일 관계로 매핑하면서, 이미 저장된 방을 다시 저장하거나 식별자를 해석하려 했다.
- 해결 — 완료 기록에는 방 ID와 완료 시각만 저장하고, DB 외래 키로 방과의 관계를 유지했다. 방장의 수동 삭제와 7일 후 자동 정리 모두 기존 논리 삭제를 재사용해 정산·참여 기록을 보존한다.
- 확인 — 수정 후 방 흐름 통합 테스트가 통과했고, 사용자가 휴대폰에서 방장의 정산 완료 방 삭제를 확인했다.

## 2026-11-23 — 정산 완료 7일 경계 테스트 실패

- 오류 — 완료 시점에서 정확히 7일이 지난 방을 정리해야 하는 테스트가 완료 상태로 남아 실패했다.
- 원인 — Java `Instant`의 나노초 정밀도와 DB `DATETIME(6)`의 마이크로초 정밀도가 달라, 경계 시각 비교가 어긋났다.
- 해결 — 완료 시각을 DB 정밀도인 마이크로초 단위로 저장하도록 맞췄다.
- 확인 — 7일 직전·경계·직후와 다른 상태의 방 유지 테스트를 포함해 백엔드 전체 30개, 프런트엔드 9개, 타입 검사와 린트가 통과했다. 실제 7일 경과는 휴대폰에서 기다려 확인하지 않았으며 자동 테스트로 검증했다.
