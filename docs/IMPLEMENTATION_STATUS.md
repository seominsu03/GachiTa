## 어느 정도 구현되었나

김동민 P0 7개 기능 항목 모두 프론트엔드·백엔드 코드가 있습니다. 가입부터 방 생성·신청·승인까지 실제 로컬 HTTP와 웹 실행으로 확인할 수 있는 단계입니다. 정산 서버도 구현되어 있으나 서민수의 가상 운행 완료와 연결되지 않아 전체 앱 흐름의 완료로 계산하지 않습니다. 임의의 완료율 대신 다음 검증 범위로 판단합니다.

| 담당 기능 | 현재 구현 | 확인 범위 |
|---|---|---|
| 회원가입·로그인·로그아웃 | 폼·서버 세션·BCrypt·CSRF·중복/입력 검증 | H2 서버 테스트, 실제 HTTP |
| 회원정보 | DB 저장·내 정보·마이페이지 | H2 서버 테스트, 실제 HTTP |
| 택시방 생성 | 출발/도착 좌표·미래 일시·2~4명 | H2 서버 테스트, 실제 HTTP |
| 목록·검색·상세 | 목적지 검색·상세·내 동승방 | H2 서버 테스트, 실제 HTTP |
| 신청·승인·거절·취소 | 상태 검증·방장 권한·중복 방지·정원 잠금 | H2 서버 테스트, 실제 HTTP, 동시 승인 테스트 |
| 정산 계산 | 원 미만 버림·방장 포함 1~4명·나머지 차액 | 프론트 로직과 H2 서버 테스트 |
| 요금 입력·수령 확인 | SETTLING에서 방장 입력·수령 확인 저장·전체 완료 | H2 서버 테스트. 실제 운행 후 UI 연결은 미완료 |

정산 예: 10,003원 / 4명 = 1인 2,500원, 차액 3원. 기존 공통 정책대로 차액을 임의로 인원별 추가 배분하지 않고 별도 표시합니다. 실제 송금·결제는 없습니다.

## 2026-11-25 사용자 신고 (`feature/ride-history-integration` 작업 브랜치)

## 2026-11-25 신청자 프로필·미응답 경고·거리 검색

- 채팅에서 서버가 60초 미응답 퇴장을 확인하면 경고 모달을 한 번 표시한다. 재참여 제한은 기존 서버 정책을 유지한다.
- 홈/택시방 목록에서 출발지 또는 목적지의 서울·경기 장소를 찾아 선택하거나 GPS 현재 위치를 선택하고 100m·300m·500m·1km 직선거리 검색을 적용한다. 반경 버튼 변경은 현재 기준점에 즉시 재적용된다. 일반 텍스트 검색이나 거리 조건 해제로 기존 좌표 조건을 지울 수 있다.
- 서울·경기 장소 결과와 GPS 지역 확인은 실제 주소/행정구역 기반이다. 전체 방 목록의 metro 필터는 수도권 좌표 범위이므로 인접 지역이 일부 포함될 수 있다. 정확한 서울/경기 경계만으로 방을 제한하는 폴리곤 필터는 포함하지 않는다.
- 검증: 백엔드 전체 46개, 프런트 로직 12개, 타입 검사·린트 통과. 프로필 권한·개인정보 비노출·후기/이용 횟수, 네 가지 반경·좌표 검증·100개 제한 전 거리 적용을 검사했다. 카카오 검색·행정구역 공급자 응답은 로컬 모의 서버로 검사했다.
