## 탑승 확인 시연 UI

- 방 101에서 방장의 ‘부르기’, 요청 상태와 60초 타이머를 표시한다.
- 방 102에서 참여자의 수락·탑승 포기·만료 상태를 시연한다.
- 방장과 참여자에게 각자 필요한 버튼만 표시한다.
- 탑승 확인 카드는 채팅 흐름에 표시되며 새 메시지는 카드 뒤에 쌓인다.
- 탑승·채팅 테스트 14개와 TypeScript 검사 통과.
- Android JS 번들 생성과 390px 브라우저 화면·버튼 동작 확인.
- 사용자 피드백: 실제 퇴장을 제외한 시연 동작 확인.

## 가상 택시 시연 UI

- 채팅방 상단에서 가상 택시 시연 화면으로 이동한다.
- 방 101의 방장은 호출 전 → 호출 중 → 배차 완료 → 운행 중 → 정산 대기 순서로 버튼 전환하며, 호출 중 취소할 수 있다.
- 방 102의 참여자는 배차 완료 예시 상태를 조회하며 단계 전환 버튼은 없다.
- 앱 실행 중 방별 마지막 단계를 유지해 채팅을 다녀와도 이어진다. 앱 재실행이나 다른 기기와는 상태가 공유되지 않는다.
- 택시·탑승·채팅 테스트 20개와 TypeScript 검사 통과.
- 390px 브라우저에서 화면 이동·단계 유지·가로 넘침 없음 확인.
- 2026-11-14 실제 Android Expo Go에서 사용자가 화면 이동과 호출 중 단계 유지가 정상 동작한다고 확인.

## 실행·검사 방법

프로젝트 폴더 `D:\ReactNative\GachiTa`에서 실행한다.

- 패키지 설치 `npm.cmd ci`
- 앱 실행 `npm.cmd start -- --lan`
- 메시지 테스트 `node --test tests/chat.test.cjs`
- 전체 시연 테스트 `node --test tests/chat.test.cjs tests/boarding.test.cjs tests/taxi.test.cjs`
- 타입 검사 `node node_modules/typescript/bin/tsc --noEmit`

휴대폰은 PC와 같은 Wi-Fi에 연결하고 Expo Go에서 QR 코드를 스캔한다.

## 화면 연결

홈 → 채팅 시연 목록 → 채팅방 → 가상 택시 시연 → 채팅방

- 홈 `/`
- 채팅 목록 `/chats`
- 채팅방 `/rooms/[roomId]/chat`
- 가상 택시 시연 `/rooms/[roomId]/taxi`

## 남은 작업과 알려진 사항

- 기능 브랜치의 PR 검토와 `dev` 통합 테스트는 아직 진행하지 않았다.
- 예정된 빈 화면 파일에서 기본 export 경고 발생
- ESLint는 사용자 요청으로 제거한 상태
- 방 101과 102의 요청은 별도 시연 상태이며 다른 기기로 전달되지 않는다.
- 탑승 확인 서버 기능(요청·수락 API, 서버 기준 60초 만료, 자동 퇴장, 동일 방 재참여 제한)은 서민수 담당이며 미구현이다. 공통 서버 구성과 참여 상태 변경 방식은 김동민 담당 기능과 협의한 뒤 연결한다.
- 택시 단계와 차량·위치·예상 정보는 시연 데이터다. 택시 상태 API, 지도·경로 조회, 정산 화면 연결은 미구현이다.

## 다음 개발

서민수 담당 지도·위치 선택 UI를 별도 단계로 진행한다. 공통 서버 데이터 계약이 준비되면 탑승 확인 API·자동 퇴장과 가상 택시 상태 API를 연동하고, 정산 화면 연결과 `dev` 통합 테스트는 담당자와 협의한다.
