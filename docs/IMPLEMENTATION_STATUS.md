## 어느 정도 구현되었나

김동민 P0 7개 기능 항목 모두 프론트엔드·백엔드 코드가 있습니다. 가입부터 방 생성·신청·승인까지 실제 로컬 HTTP와 웹 실행으로 확인할 수 있는 단계입니다. 정산 서버도 구현되어 있으나 서민수의 가상 운행 완료와 연결되지 않아 전체 앱 흐름의 완료로 계산하지 않습니다. 임의의 완료율 대신 다음 검증 범위로 판단합니다.

| 담당 기능 | 현재 구현 | 확인 범위 |
|---|---|---|
| 회원가입·로그인·로그아웃 | 폼·서버 세션·BCrypt·CSRF·중복/입력 검증 | H2 서버 테스트, 실제 HTTP |
| 회원정보 | DB 저장·내 정보·마이페이지 | H2 서버 테스트, 실제 HTTP |
| 택시방 생성 | 출발/도착 좌표·미래 일시·2~4명 | H2 서버 테스트, 실제 HTTP |
| 목록·검색·상세 | 목적지 검색·상세·내 동승방 | H2 서버 테스트, 실제 HTTP |
| 신청·승인·거절·취소 | 상태 검증·방장 권한·중복 방지·정원 잠금 | H2 서버 테스트, 실제 HTTP, 동시 승인 테스트 |
| 정산 계산 | 원 미만 버림·방장 포함 1~4명·나머지 차액 | 프론트 로직과 H2 서버 테스트 |
| 요금 입력·수령 확인 | SETTLING에서 방장 입력·수령 확인 저장·전체 완료 | H2 서버 테스트. 실제 운행 후 UI 연결은 미완료 |

정산 예: 10,003원 / 4명 = 1인 2,500원, 차액 3원. 기존 공통 정책대로 차액을 임의로 인원별 추가 배분하지 않고 별도 표시합니다. 실제 송금·결제는 없습니다.

## 2026-11-17 B 탑승 확인 서버 연동·화면 동선 — 4단계

작업 브랜치: `feature/boarding-integration`. 기존 `feature/boarding`과 통합 전 보존 브랜치는 유지한다.

### 구현

- 탑승 확인 요청·응답과 서버 기준 60초 만료를 MySQL에 저장하도록 연결했다. 미응답자는 자동 퇴장하며 같은 방에 재신청할 수 없다.
- 방장은 동승자 관리 화면에서, 승인된 참여자는 택시방 상세 화면에서 채팅방으로 이동할 수 있다. 승인 대기 중인 참여자의 상세 화면은 주기적으로 갱신한다.
- 채팅방에 홈·택시방·채팅·내 정보 메뉴와 택시방 상세로 돌아가는 버튼을 추가했다.
- 정원이 차면 `모집 완료`로 표시한다. 택시방 목록에는 정산 완료 전까지 방을 표시하고, 정산 완료된 방은 제외한다.
- 출발 시간이 지나지 않았고 시간 초과로 빈자리가 생기면 방을 다시 모집 가능 상태로 전환한다. 방장은 정원이 다 차지 않아도 승인된 동승자가 1명 이상이면 탑승 확인을 시작할 수 있다.
- 퇴장 안내와 이동 버튼을 화면의 남은 공간 가운데에 놓도록 배치를 수정했다.

### 확인 결과

- 사용자는 휴대폰 두 대에서 신청·승인 후 채팅 이동, 하단 메뉴, 정원 미달 탑승 확인, 시간 초과 퇴장과 재모집, 택시방 목록 상태가 의도대로 동작한다고 확인했다.
- 사용자가 `npm run typecheck`와 `npm run lint`를 실행했고 오류가 없다고 보고했다.
- 사용자가 `.\mvnw.cmd test`를 실행한 결과 백엔드 H2 테스트 25개 통과, 실패 0개, 오류 0개, `BUILD SUCCESS`를 확인했다.
- 퇴장 안내 화면의 배치 수정 **후** 실제 휴대폰 화면은 아직 확인하지 않았다. 다음 휴대폰 테스트 때 확인한다.

### 남은 연동

- 채팅 메시지는 기기 안에서만 표시된다. 기기 간 송수신과 메시지 기록 저장은 미구현이다.
- 실제 택시 호출·운행은 아직 연동하지 않았다. 실제 도로 경로·예상 시간 연동은 아래 지도 통합 단계에서 반영했다.
- 정산 완료 후 택시방 목록에서 제외되는 동작은 코드에 반영했으나, 휴대폰에서 정산 완료까지 진행한 확인 결과는 아직 없다.
