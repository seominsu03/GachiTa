# 채팅 UI 0·1단계 구현 계획

> 승인 범위: 2026-11-11 대화의 0단계 화면 연결과 1단계 채팅 기본 UI. 이 세션에서 직접 구현하며 commit·push하지 않는다.

**목표:** 기존 Expo 예제를 보존하고 채팅 시연 목록 → 방 → 뒤로 가기, 메시지 입력·표시를 확인한다.

**기준:** `docs/team_roles.md`, `GachiTa_COMMON_DEV_RULES.md`, 승인된 사용자 시나리오.

**구조:** 루트 Stack에 기존 index/explore와 채팅 경로를 연결한다. 채팅 시연 데이터와 화면 상태는 별도 provider에서 앱 실행 동안만 관리한다. 실제 인증·채팅 API·DB는 연결하지 않는다.

**기술:** 설치된 Expo 58, Expo Router, React Native, TypeScript. 새 의존성을 설치하지 않는다.

## 제약과 공통 변경

- 공통 파일 변경은 루트 `_layout.tsx`의 화면 연결로 한정해 사용자에게 사전 보고했다. 기존 공통 theme, API, 인증 상태, package.json은 변경하지 않는다.
- 기존 index/explore 화면과 에셋은 보존한다. 루트 탭 대신 Stack을 사용하고 상단 버튼으로 두 예제 화면과 채팅 시연을 연결한다. 제품의 최종 하단 탭은 이후 공통 작업으로 남긴다.
- 새 `ChatMessage`, `DemoChatRoom`은 채팅 시연 UI 모델이며 공통 서버 DTO를 확정하지 않는다.
- 잘못된 방 ID는 오류 화면으로 처리한다. 메시지는 방별로 구분하며 재실행/새로고침 시 초기화된다.
- 공백 메시지 거부, 최대 500자, 전송 후 입력 초기화, 키보드 표시 중 입력 가능, 긴 메시지 줄바꿈, 하단 최신 메시지 표시를 검증한다.
- 60초 요청·방장 권한의 실제 검증, 지도, 택시, 다른 담당 기능은 이번 범위에 포함하지 않는다.
